# Working on PopSpell

Read [PRODUCT.md](PRODUCT.md) before planning a product or interface change. It states PopSpell's purpose, users, learning principles and scope. Use [README.md](README.md) for the current feature inventory and [help.html](help.html) for teacher-facing instructions.

When a requested change revises the product direction, follow the user's decision and update PRODUCT.md in the same change. Keep year group separate from working level, and preserve teacher judgement when using assessment or progress data. Check age-appropriate presentation, accessibility, pupil privacy and the pupil app's offline use where they apply.

Before publishing code changes, run `npm run build`, `npm test` and `npm run check`. Keep product claims and feature counts in documentation aligned with the checked content.
